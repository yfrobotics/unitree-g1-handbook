# 连接机器人

本页先建立开发电脑到 G1 EDU 开发计算单元的有线连接，再验证 SSH。完成后，你应能登录机器人、查看系统信息，并确认后续 DDS 通信使用的网卡。

## 先确认连接对象

区分用于运行用户程序的开发计算单元和负责运动控制的计算单元。本手册早期使用的设备配有 Jetson Orin；实际计算模块、开放端口和账户信息取决于交付配置。先向设备管理员确认，避免把运动控制器当作通用开发主机操作。

下面沿用本手册原有设备的 `192.168.123.164` 地址作为示例。它不是对所有 G1 固定地址的保证。若交付资料给出了其他地址，请同步替换命令和子网设置。

## 接线与地址

初次调试可用网线直连，或将开发接口和电脑接到同一交换机的 LAN 端口。暂时不要通过路由器 WAN 端口或访客 Wi-Fi 建立 DDS 连接。

```text
G1 开发接口 —— 网线 —— 开发电脑
```

以下是同一子网的配置示例；宇树 ROS2 文档也使用电脑地址 `192.168.123.99/24`。设置前确认该地址未被其他设备占用。[官方网络配置说明](https://github.com/unitreerobotics/unitree_ros2#connect-to-unitree-robot)

| 项目 | 示例设置 |
| --- | --- |
| 机器人开发计算单元 | `192.168.123.164`，以交付资料为准 |
| 开发电脑的有线 IPv4 | `192.168.123.99` |
| 子网掩码 | `255.255.255.0`，即 `/24` |
| 有线连接默认网关 | 直连时留空 |
| 有线连接 DNS | 直连时留空 |

在 Ubuntu 的“设置 → 网络 → 有线连接 → IPv4”中选择手动配置，填写上述地址和掩码并重新连接。电脑若另有上网 Wi-Fi，应保留其默认路由。

## 确认网卡和路由

下面命令在**开发电脑**执行：

```bash
ip -br link
ip -br addr
ip route get 192.168.123.164
ping -c 4 192.168.123.164
```

记下连接机器人的网卡名称，例如 `enp3s0` 或 `enx...`。路由查询结果中的 `dev` 应指向这块有线网卡，`src` 应为刚配置的电脑地址。若流量走向 VPN 或 Wi-Fi，先解决重叠子网或路由选择问题。

`ping` 成功表示 IP 层可达；它不能证明 SSH 服务、DDS 发现或控制接口已就绪。

## 通过 SSH 登录

```bash
ssh unitree@192.168.123.164
```

账户名和密码以设备管理员或交付记录为准。本手册原有设备使用 `unitree` / `123`，已修改过密码的设备不适用。首次连接时先核对主机指纹；若已知主机指纹突然变化，应确认是否更换设备或重装系统。

登录后可执行以下只读检查，确认连接到预期主机：

```bash
hostname
uname -m
cat /etc/os-release
ip -br addr
```

将架构和系统版本记录下来，供选择 SDK 依赖时使用。`aarch64` 和 `x86_64` 的二进制文件不能直接混用。

## 为 SDK 通信做准备

SDK 的网络参数通常是**运行该程序的主机上的网卡名称**，不是机器人 IP。程序在电脑上运行时使用电脑的有线网卡；程序在机器人上运行时，要重新检查机器人本机的接口。

连接成功后先完成 [SDK 配置](../development/sdk-setup.md)或 [ROS2 状态读取](../development/ros2.md)。如果 SSH 正常而状态订阅失败，转到[故障排查](../troubleshooting.md)，检查 DDS 域、消息类型和组播。
