# 连接互联网

连接机器人和让机器人上网是两个独立步骤。本页以已能通过有线 SSH 登录开发计算单元为前提，配置用于下载代码和依赖的互联网连接。

## 选择网络布局

最容易排查的布局是保留有线开发连接，再为开发计算单元配置独立的上网接口：

```text
开发电脑 —— 有线开发网络 —— G1 开发计算单元
                                  |
                                Wi-Fi
                                  |
                            路由器 —— 互联网
```

这要求开发计算单元确实有可用的 Wi-Fi 接口。机器人能够通过 App 联网，并不自动说明用户登录的计算单元已获得相同的网络连接。

| 方案 | 适用情况 | 需要确认 |
| --- | --- | --- |
| 开发计算单元连接 Wi-Fi | 有可用无线接口 | 上网子网与机器人内部子网不重叠 |
| 独立网口或 USB 网卡上网 | 无无线接口，或实验室只提供有线网络 | 新接口的驱动、地址和默认路由 |
| 电脑共享网络 | 临时下载依赖 | 共享功能可能重设有线地址并启用 DHCP；先规划子网 |

仅把网线插进路由器，不会自动替静态地址设备补上网关和 DNS。不要修改机器人内部控制网络来迁就上网网络。

## 使用 NetworkManager 配置 Wi-Fi

以下命令在**机器人开发计算单元**上执行，并且仅适用于由 NetworkManager 管理无线网络的系统。保留现有有线 SSH 连接作为配置通道。

```bash
nmcli general status
nmcli device status
nmcli device wifi list
```

确认存在 Wi-Fi 设备且没有被禁用。将下例中的 `实验室网络` 替换为实际 SSID；密码通过交互提示输入：

```bash
sudo nmcli --ask device wifi connect '实验室网络'
```

`--ask` 可在需要时请求凭据，连接命令会创建或使用网络配置。多块无线网卡的系统可按实际接口添加 `ifname` 参数。企业认证网络应使用管理员提供的证书和配置。[NetworkManager 命令说明](https://networkmanager.dev/docs/api/latest/nmcli.html)

若系统没有 `nmcli`，应先识别已有网络管理方式；不要为了运行本页命令直接替换机器人预装的网络服务。

## 分层验证

```bash
ip -br addr
ip route
ip route get 1.1.1.1
getent hosts github.com
curl -I --connect-timeout 10 https://github.com
```

依次确认：上网接口有地址、外网路由走该接口、域名能解析、HTTPS 能连接。某一步失败时，先修复这一层，再测试软件安装。

| 现象 | 优先检查 |
| --- | --- |
| 连上 Wi-Fi 但无 IPv4 地址 | DHCP、无线认证、接入设备数量限制 |
| 有地址但无外网路由 | 默认网关及连接配置 |
| IP 可达但域名解析失败 | DNS 配置、实验室 DNS 策略 |
| DNS 正常但 HTTPS 失败 | 系统时间、代理、认证门户及出口策略 |
| 上网后机器人连接失效 | 子网重叠、默认路由抢占、共享网络重设地址 |

实验室可能禁止直接访问外部 DNS 或部分站点，应使用管理员批准的配置。不要把网络失败简单归因于机器人故障。

## 更新与下载

先在开发目录或虚拟环境中安装项目依赖，并记录软件版本。机器人系统镜像、驱动和固件的整体升级应遵循对应版本的官方流程，避免一次更新多个层次后无法定位兼容性问题。

下载完成后再次从电脑测试 SSH 和状态订阅，确认上网配置没有影响开发网络。若只需传递文件，也可以在电脑下载后通过 `scp` 传入机器人，无需长期共享互联网。
