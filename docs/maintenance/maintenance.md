# 日常维护、备份与更新

日常维护的目标是保持设备配置可追溯，并在异常出现时保留足够信息。以下是实验室工作流程建议；电池限值、机械紧固、固件刷写和故障维修采用交付版本的官方说明，不把软件教程当作维修手册。

## 实验前后

| 时点 | 检查与记录 |
| --- | --- |
| 每次启动前 | 电池与锁扣、线缆磨损、脚底、关节异物、传感器窗口、支撑结构 |
| 增加附件后 | 固定方式、线缆活动余量、质量和安装位姿、碰撞模型与相机外参 |
| 每次实验后 | 告警、温度趋势、异常声音、人工接管、正常关机与充电安排 |
| 长期存放前 | 电池处置、清洁、防潮、附件清点、设备记录归档 |

BrainCo2 检查串口连接、手指覆盖件、线缆张力与空载状态。发现破损或异常阻力时停止使用，不通过反复握拳测试机械故障。紧固件扭矩及拆装步骤由厂家资料确定，不提供通用数值。

## 电池、充电与存放

使用与电池匹配的官方充电器。充电前查看外观、连接器和告警；鼓包、漏液、异味或异常发热按设备负责人流程处理。充电环境、温度范围、长期存放电量和检查周期需抄录**该型号**说明到设备记录，不从其他机器人电池规格推断。

依据：[G1 电池与充电器说明](https://marketing.unitree.com/article/en/G1/Battery_Charger.html)及[使用说明](https://marketing.unitree.com/article/en/G1/User_Manual.html)。正常关机先完成落座或支撑流程，见[安全指南](../getting-started/safety.md)。

## 备份用户开发环境

在 PC2 的用户目录记录软件信息；不要把明文凭据纳入公开仓库：

```bash
mkdir -p ~/g1-backups/session-2026-09-26
uname -a > ~/g1-backups/session-2026-09-26/kernel.txt
cat /etc/os-release > ~/g1-backups/session-2026-09-26/os-release.txt
ip -br addr > ~/g1-backups/session-2026-09-26/interfaces.txt
ip route > ~/g1-backups/session-2026-09-26/routes.txt
python -m pip freeze > ~/g1-backups/session-2026-09-26/python-requirements.txt
```

在实际虚拟环境中执行 `pip freeze`。另存各仓库 `git rev-parse HEAD`、子模块状态、本地修改、相机配置、标定、服务启动参数和模型哈希。原始演示先复制到第二份存储并验证校验值，再考虑清理采集磁盘。示例日期替换为实际会话。

不要把私钥、无线密码或整个家目录直接作为“日志”上传。网络配置、服务文件与证书可在受控备份中保留，公开问题报告只包含必要且脱敏的信息。

## 分层更新与回滚

1. 保存当前可工作的配置清单、代码提交和验收输出。
2. 在新目录/虚拟环境更新用户程序，先做导入、状态订阅和离线模型测试。
3. 对新环境执行同一套验收，确认行为一致后再改服务启动路径。
4. 失败时切回旧用户环境，保留新环境日志；不要同时重装系统、升级固件和改 DDS。

系统镜像、JetPack、驱动、控制器固件和电机固件不属于普通 Python 回滚范围。更新前要有与机型和序列号匹配的官方支持流程及恢复介质，不能假定 `git checkout` 或 `apt downgrade` 能恢复机器人固件。

## 出现异常时保留什么

先按[安全流程](../getting-started/safety.md)结束当前实验，再记录 App 告警、状态、温度、时间点、命令来源和最近改动。软件进程异常可保存自己的服务日志；涉及机械、电池或控制器问题，交给设备负责人或官方支持处理，不反复重现危险动作来补充日志。

使用[实验记录模板](records.md)和[故障报告格式](../troubleshooting.md#issue-report)统一信息。
